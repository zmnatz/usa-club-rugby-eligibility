# The screens are plain HTML and CSS, with one small script

The site and the component package used MUI and Emotion. Every page carried MUI's runtime, Emotion's, React's hydration of a table of hundreds of cells, and a theme's worth of CSS variables, to show text, links and tables from data that is fixed at build time. The site is static, so this cost every visitor on every page for nothing they could see. This supersedes the MUI decisions in ADR 005; the rest of 005 (peer dependencies, no framework, the host owns navigation, hosts supply the data) stands.

Decisions, so they are not "fixed" later:

- **Semantic HTML and one stylesheet.** `packages/usa-club-rugby-components/src/styles.css` holds every style, as `ec-` classes on `--ec-*` custom properties, with a dark scheme under `prefers-color-scheme`. A host retheme overrides the variables. The package sets no page background, font or heading styles. The site's own chrome and prose are in `src/styles/site.css`, on the same variables.
- **CSS does what CSS can.** A club's sides are all on the page, with in-page links between them, rather than tabs. The status filter is radio buttons and `:has()`, the optional columns are checkboxes in a `<details>`, and the skip link is an anchor to a focusable row. None of these need a script. `:has()` is in every current browser; in one without it the filter and column choice do nothing and every row and column is shown, which is a safe failure.
- **One script, listening on `document`** (`enhance.ts`, exported as `ENHANCEMENT_SCRIPT`, put in `_document`). It sorts a table by a column's `data-sort` values, filters the club directory, and downloads the export. It uses event delegation, so it covers markup React adds in the browser (the CSV report, a Locked Season's pages) as well as static HTML, and it can be included twice. Without it, every table is complete and in name order.
- **The export text is in the page.** `buildReport` runs when the page is rendered and its text goes in a `<template>`; the button downloads it. A club page needs no data and no React to export. The report is stamped with when the records were last updated, not the visitor's clock, so the page is the same every time it is built from the same data.
- **No player dialog.** A player's page already shows everything the dialog did, with more room. A row's name links to it, as every row did through "Open as a page", and a link works from the keyboard, middle-click and a shared URL without the code a modal needs. A Locked Season's and a CSV report's players have no page, so they show only the table, whose Reason column carries the verdict. The per-competition rounds grid the dialog showed for a CSV report is gone: those rounds are in the file the visitor uploaded.
- **No React in the browser where it isn't needed.** The home page, club pages and stats pages ship no Next runtime (`unstable_runtimeJS: false`), only inline scripts: this one, and one that reloads on history navigation (`historyReload.ts`). The 404 page's old-link redirect is an inline script built from the tested `legacyPlayerId`. The player page, the Locked Season page and the CSV report still run React, because they load data or take a file in the browser (ADR 006 and 007); they no longer carry MUI.
- **The package is a breaking change.** Version 0.9.0 drops the MUI and Emotion peers, removes `PlayerEligibilityDialog`, and changes the props listed in the package README.

Not decided here: serving the player page from a server (ADR 007), which would let it drop React too.
